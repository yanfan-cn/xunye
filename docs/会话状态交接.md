### 0.B 闪退根因（勿再犯）

完整表见 [`docs/液态玻璃与动画安全.md`](./液态玻璃与动画安全.md)（SPEC-100）。

1. **NTP backdrop**：把 `layerBackdrop` 包在含 `browserControlLiquidGlass` 的同一树上 → RenderThread `computeTransformImpl` 递归 **SIGSEGV**。壁纸采样层与玻璃控件须为兄弟；无壁纸时 `LocalTopBarBackdrop=null`。
2. **标签页 + 液态玻璃（2026-10-08）**：有网页时开标签，`RenderThread` `SIGSEGV`，原因 `stack overflow` / `computeTransformImpl`（约 512 帧）。**仅液态玻璃模式**复现；填充模式相对安全。log：`_tabs_click_log.txt`、`_tabs_click_log_110.txt`。
3. **已证明无效/不足**：071 双侧 scale；075 恢复 0.88 scale+pause；076 临时 suppress 玻璃+pause；077 玻璃仅 fade、填充仍 scale——**11.0 仍闪**；078 仅 180ms fade——**11.1 仍闪**。
4. **当前策略（SPEC-079 / 11.2 真机已暂时解决；087/100 标签用 slide-only）**：删标签**底部** ClearAll 玻璃键；标签页 `AppScaffold(disableLiquidGlass/disableContentSampling)`；顶栏返回/新建强制 Tonal；标签 Nav **slide-only（禁 fade/scale）**。手机关全部=长按计数菜单；**080 平板**标签页顶栏另有 Tonal「全部关闭」。**勿恢复底部玻璃 ClearAll 或标签 Nav fade/scale。**
5. **缩略图**：host `draw` 到软件 Bitmap，**禁止**当液态玻璃采样源；后台标签只显示离开时快照。**081**：平板卡片比例跟屏幕宽高比。
6. **设置闪退（SPEC-081）**：平板设置一级液态玻璃返回同样会 `computeTransformImpl` 栈溢出 → 一级返回 **Tonal** + 设置页 `disableLiquidGlass`。**勿再让平板设置 L1 返回跟表面样式开玻璃。**
7. **网页→NTP（SPEC-100）**：`clearActiveToNtp` **勿立即 destroy**；会话滑出完成后再 `releaseSessionHostIfParked`。

### 0.7 净读图片/视频位排障经验（SPEC-225~228，2026-11-03 定案，出问题先查这里）

净读视频位黑块/图片空白曾由**三个独立根因叠加**，修复分散在 2.3.1/2.3.2。复发时按此排查：

1. **缓存 key 错位（真凶，2.3.2 修）**：排版走 `LegacyReaderChapterPaginator→ImageProvider.getImageSize(book, src带#browsesth-jingshi)`，
   缓存文件名 = `MD5Utils.md5Encode16(带片段src)`；显示走 `ReadBookController.loadReaderImage`。
   两侧 src 必须一致（现在都用带片段原 src），否则永远 miss → 「缺图不画」→ 黑块。
   验证法：对疑似 src 算 `md5Encode16`（MD5 hex 的 8..24 位）与 `book_cache/<书>/images/` 文件名比对。
2. **CDN 按 Accept 头给 AVIF（2.3.1 修）**：`BrowserWebImageHeaders` 的 Accept 绝不能再写 `image/avif`——
   本机 HEIF 栈解不了 AVIF（logcat 特征：`HeifDecoderImpl: getSize: not supported!`），且坏字节会以 .jpg 名字缓存。
   兜底：`BookHelp.checkImage` 的 `isAvifFile` 魔数检查 + `ImageProvider.cacheImage` 对失效缓存就地重下。
3. **伪协议炸建书（2.3.1 修）**：`browsesth-jingshi://` 进 `HtmlFormatter.formatKeepImg`（内部 `java.net.URL` 解相对路径）
   抛 `unknown protocol` 会中断 `createEphemeralBook`。`normalizeMixedHtml` 已做掩码/还原；
   新增伪协议 src 时必须同步掩码。

**排障方法论（这次能定位全靠它，复用）**：
- logcat 过滤 `AppLog|图片|下载失败|HeifDecoderImpl|unknown protocol`（`AppLog.put` 会以 `Log.e(className, msg)` 进 logcat）。
- 缓存文件验格式：`adb pull` 下来看魔数（WebP=`RIFF..WEBP`；AVIF=`..ftyp avif`；JPEG=`FF D8`）。
- 看真实渲染：`adb shell screenrecord` + ffmpeg 抽帧（本机 ffmpeg 已装），比反复问「好了没」高效。
- 正文 HTML 真容：直接拉 `book_cache/<书>/00000-*.nb` 看 img src。
- 注意：操作者测试的文章可能不是你分析的那篇——先问清/从录屏确认 URL。
