## 1. 改动前事实（这是回答用户问题的依据）

| 数据 | 存储 | 原备份是否包含 |
| --- | --- | --- |
| 浏览器「收藏」（网页书签 + 多层文件夹 + 排序） | SP `browsesth_browse_store` | **否** |
| 浏览器「历史记录」 | 同一 SP 的 `history` 键 | **否** |
| 主页快捷书签 / 壁纸 / 搜索引擎 | `browsesth_ntp_prefs`、`browsesth_ntp_shortcuts`、`browsesth_browser_chrome` | 否 |
| 标签页会话 / 密码 / 自动填充 / 站点设置 / 下载记录 | 各自 SP | 否 |
| 阅读书签（Room `bookmarks`）、划线笔记 | 数据库 | 是（备份项「书签」指的**是阅读书签**，容易被误解成浏览器收藏） |
| 书架、书源/RSS、阅读记录、阅读搜索历史、主题/阅读/封面配置、DataStore 设置 | JSON + `config.xml` | 是 |

取证：`Backup.backupFileNames` 仅含上述 JSON 与 `config.xml`；`config.xml` 只导出 `AppConfigStore`（`settings` DataStore）。全局搜索 `BrowseStore` 在 `Backup`/`Restore`/WebDav 层零引用。

## 3. 数据合同

```json
{
  "version": 1,
  "history":   [{"url":"…","title":"…","at":0,"lastOpened":0,"folderId":"","order":0}],
  "bookmarks": [ ... 同结构 ... ],
  "folders":   [{"id":"…","name":"…","order":0,"parentId":""}]
}
```

- 缺字段取默认值；未知字段忽略；损坏 JSON 返回 `null`（不抛）。
- 旧备份无此文件 → 恢复直接跳过，向前兼容。

## 4. 恢复策略（为什么是合并）

用户明确要求「本地数据不能被备份反向破坏」，因此：

1. 收藏 URL 已存在 → 保留本地标题/文件夹（不覆盖用户改名）。
2. 文件夹 id 相同**且同名同父** → 视为同一文件夹；否则新建并重映射，保证层级不丢。
3. 同父同名 → 复用，不重复创建。
4. 父链缺失或成环 → 回落根目录，绝不丢条目。
5. 历史 URL 已存在 → 时间取较新；否则追加，按 `at` 倒序截断到 100。
6. 重复恢复幂等。

## 6. 失败记录

1. `BrowseStoreBackupTest` 首轮全失败：Robolectric 未指定 `application`，启动真 `App.onCreate` 时 `appCtx` 未初始化。已按既有 `BrowseStoreImportSinkTest` 口径传 `application = Application::class`。
2. 「文件夹 id 冲突」用例首轮 `NoSuchElementException`：暴露「同 id 一律沿用本地」会静默丢弃备份中内容不同的文件夹。已改为同名同父才复用。

## 7. 未验证项 / 已知边界

- 真机「备份→删数据→恢复」闭环未跑（构建期间无 adb 设备）。
- 备份忽略项新增一行 UI：设置在 `IgnoreItemsSheet` 内按 key 列表自动渲染，未单独截图确认排版。
- 本轮不备份：密码、自动填充、站点设置、标签页会话、下载记录、浏览器搜索历史（`browsesth_search_history`）。属刻意边界。
- 浏览器收藏**仍只有导入（其他浏览器 HTML），没有导出**；如需换到其他浏览器，需另立 Spec。
