## 1. 问题与根因

截图 `Screenshot_20261121_211610_…jpg`（深色主题 + 赛博壁纸，填充表面）中搜索框内文字、图标全黑不可见。

逐像素取证：胶囊底 `(24,28,31)`，胶囊内文字 `(27,27,27)` —— 正是 `NtpDarkWordmark #1C1B19`，对比 **1.0:1**。

根因不是「没做自适应」，而是 SPEC-269 在自适应规则里留了一条绝对分支：

```text
useDarkInk(fieldBgLuminance, darkPresetWallpaper) = darkPresetWallpaper || 亮度 >= 0.45
```

壁纸是赛博/霓虹就无条件深墨，完全不看胶囊实际底色；同时判定只取 `fieldBg`，**未计入液态玻璃透明度（浅 0.4／深 0.35）叠加背景后的真实底色**，所以「深色主题 + 浅色壁纸」会反向出现白压白。

## 2. 实际改动

| 文件 | 改动 |
| --- | --- |

## 3. 关键设计取舍

- **壁纸只提供背景色，不提供结论**：是否深墨改由合成底色决定，同一壁纸在深浅主题下会得到不同墨色（有专门回归用例）。
- **垫色是兜底而非主路径**：正常组合 `scrimAlpha = 0`；只有落在「深墨浅墨都 < 4.5:1」的死区（约 `#777`–`#83` 灰）才补垫色，上限 0.60，避免胶囊被洗成纯黑/纯白。
- **次要文字先调透明度、再考虑垫色**：占位/AI 助手这类带 alpha 的文字比主文字更容易掉到 4.5 以下，先补偿它可避免为一行小字牺牲整个胶囊背景。

## 5. 失败记录（如实）

首轮测试 17 项失败，逐项定位：

1. `BrowseStoreBackupTest` 全 9 项：`@Config(sdk=[35])` 未指定 `application`，Robolectric 启动了真 `App.onCreate` → `appCtx has not been initialized`。改为 `@Config(application = Application::class, sdk=[35])`（与既有 `BrowseStoreImportSinkTest` 同口径）。
2. `composite` 用 `toInt()` 截断导致 `0.5` 混合得 `#7F7F7F`；改为 `roundToInt()`。
3. 「中亮度垫色」用例的灰值 `#767676` 不在死区内（该灰下深墨恰好 4.5+），改用死区内的 `#7B7B7B`。
4. 文件夹 id 冲突用例暴露实现缺陷：原逻辑「同 id 一律沿用本地」会让备份里内容不同的同名 id 文件夹丢失。改为「同 id **且同名同父**才复用，否则新建并重映射」。
5. `次要文字透明度` 用例暴露设计缺陷：占位文字 `white@0.88` 在浅色垫底上不足 4.5:1。改为 `Decision.secondaryAlpha` 自适应下限。

**既有红测试（非本次引入，未改）**：

- `BrowserUrlPolicyTest` 4 项：纯 JVM（非 Robolectric）调用 `android.net.Uri.parse` → NPE（`BrowserUrlPolicy.kt:10`）。
- `BrowserNavHistoryTest.fallsBackToHostWhenTitleBlank` 1 项：断言期望 `host.example`，实际 `https://host.example/path`。

这两处在本轮改动前即存在（涉及文件均未被本次修改），已记入待办，未在本次 release 中处理。
